# 123 Cloud

The `cloud123` backend accesses [123 Cloud](https://www.123pan.com/). It can
also be selected with the type names `123`, `123cloud` and `123drive`.

Paths are specified as `remote:path`, and may be as deep as required, e.g.
`remote:directory/subdirectory`.

## Configuration

Run `rclone config` and choose `cloud123`. Enter your phone number or email
and password, or a token copied from a logged-in session. Expired tokens are
renewed automatically by logging in again.

```ini
[my123]
type = cloud123
user = 13800138000
pass = *** ENCRYPTED ***
```

### Hashes

MD5 is supported.

### Uploads and rapid upload

123 needs the MD5 of the file before an upload starts. If the source provides
MD5 (a local file computes it by reading the file) the data is streamed in
`chunk_size` parts (5–16 MiB) to presigned URLs, each part retried. If MD5 is
not available, or the size is unknown, the input is first copied to a
temporary file while hashing. If 123 already has the content the file is
created without transferring data. `rclone backend rapid-upload` creates a file
from its name, size and MD5.

### Modification times

Modification times are not supported; the server's update time is shown.

### Standard options

Here are the Standard options specific to cloud123 (123 Cloud / 123 Drive).

#### --cloud123-user

123 Cloud login username (phone number or email).

Properties:

- Config:      user
- Env Var:     RCLONE_CLOUD123_USER
- Type:        string
- Required:    false

#### --cloud123-pass

123 Cloud login password.

**NB** Input to this must be obscured - see [rclone obscure](/commands/rclone_obscure/).

Properties:

- Config:      pass
- Env Var:     RCLONE_CLOUD123_PASS
- Type:        string
- Required:    false

### Advanced options

Here are the Advanced options specific to cloud123 (123 Cloud / 123 Drive).

#### --cloud123-token

Existing authorization token (optional, auto-generated upon login).

Properties:

- Config:      token
- Env Var:     RCLONE_CLOUD123_TOKEN
- Type:        string
- Required:    false

#### --cloud123-root-folder-id

ID of the root folder (default '0' for root).

Properties:

- Config:      root_folder_id
- Env Var:     RCLONE_CLOUD123_ROOT_FOLDER_ID
- Type:        string
- Default:     "0"

#### --cloud123-chunk-size

Upload chunk size (5M to 16M).

Properties:

- Config:      chunk_size
- Env Var:     RCLONE_CLOUD123_CHUNK_SIZE
- Type:        SizeSuffix
- Default:     16Mi

#### --cloud123-encoding

Path encoding for 123Pan.

Properties:

- Config:      encoding
- Env Var:     RCLONE_CLOUD123_ENCODING
- Type:        Encoding
- Default:     Slash,InvalidUtf8,Dot

#### --cloud123-description

Description of the remote.

Properties:

- Config:      description
- Env Var:     RCLONE_CLOUD123_DESCRIPTION
- Type:        string
- Required:    false

## Backend commands

Here are the commands specific to the cloud123 backend.

Run them with:

```console
rclone backend COMMAND remote:
```

The help below will explain what arguments each command takes.

See the [backend](/commands/rclone_backend/) command for more
info on how to pass options and arguments.

These can be run on a running backend using the rc command
[backend/command](/rc/#backend-command).

### rapid-upload

Create a file from its hashes without uploading data.

```console
rclone backend rapid-upload remote: [options] [<arguments>+]
```

This command asks 123 Cloud to create a file from content it
already stores, identified by size and MD5. It is also available as
"rapidupload".

Usage examples:

```console
rclone backend rapid-upload cloud123:dir name size md5
rclone backend rapid-upload cloud123:dir -o name=file.zip -o size=52428800 -o md5=...
```

Options:

- "md5": MD5 of the whole file.
- "name": File name.
- "path": Directory to create the file in, relative to the remote.
- "size": File size in bytes.

### addurl

Add offline download task for url.

```console
rclone backend addurl remote: [options] [<arguments>+]
```

This command adds an offline (cloud-side) download task for a url
(http, magnet, ed2k or thunder). 123 Cloud resolves the url and
downloads all of its files. It is also available as "offline".

Usage example:

```console
rclone backend addurl cloud123:dirpath url
```

Downloads will be stored in 'dirpath', which must exist. 123 Cloud
names the downloaded files itself.

The result is the new task as JSON with the fields "id", "name",
"url", "size", "status" ("init") and "created_at".

### tasks

List offline download tasks.

```console
rclone backend tasks remote: [options] [<arguments>+]
```

This command lists the offline download tasks. It is also
available as "listoffline".

Usage example:

```console
rclone backend tasks cloud123:
```

The result is a JSON list of tasks with the fields "id", "name",
"size", "status" ("init", "running", "complete" or "error"),
"progress" and "speed".

### deltask

Delete an offline download task.

```console
rclone backend deltask remote: [options] [<arguments>+]
```

This command deletes the offline download task with the given ID.
It is also available as "deleteoffline".

Usage example:

```console
rclone backend deltask cloud123: task_id
```

## Limitations

- Modification times can't be set.
- Offline downloads can't choose the names of the downloaded files.
