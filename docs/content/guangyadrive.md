# GuangYa Drive

The `guangyadrive` backend accesses GuangYa Drive. It can also be selected with
the type names `guangya` and `guangyacloud`.

Paths are specified as `remote:path`, and may be as deep as required, e.g.
`remote:directory/subdirectory`.

## Configuration

Run `rclone config` and choose `guangyadrive`, then enter a refresh token.
Access and refresh tokens are renewed automatically and saved back to the
config.

```ini
[myguangya]
type = guangyadrive
refresh_token = ...
```

### Uploads

Uploads are streamed straight to Aliyun OSS: one PUT for files up to
`chunk_size`, a multipart upload otherwise. Each part is read into a reused
buffer and retried, so memory use is bounded and nothing is written to a
temporary file. The server may complete an upload instantly when it already has
a matching file.

### Hashes and modification times

No hashes are supported. Modification times are not supported; the upload time
is shown.

### Standard options

Here are the Standard options specific to guangyadrive (GuangYa Drive).

#### --guangyadrive-access-token

GuangYa Drive access token.

Properties:

- Config:      access_token
- Env Var:     RCLONE_GUANGYADRIVE_ACCESS_TOKEN
- Type:        string
- Required:    false

#### --guangyadrive-refresh-token

GuangYaPan refresh token for automatic token renewal.

Properties:

- Config:      refresh_token
- Env Var:     RCLONE_GUANGYADRIVE_REFRESH_TOKEN
- Type:        string
- Required:    true

### Advanced options

Here are the Advanced options specific to guangyadrive (GuangYa Drive).

#### --guangyadrive-root-folder-id

Root folder ID to start in (default empty for root).

Properties:

- Config:      root_folder_id
- Env Var:     RCLONE_GUANGYADRIVE_ROOT_FOLDER_ID
- Type:        string
- Required:    false

#### --guangyadrive-page-size

Page size for file listings.

Properties:

- Config:      page_size
- Env Var:     RCLONE_GUANGYADRIVE_PAGE_SIZE
- Type:        int
- Default:     100

#### --guangyadrive-chunk-size

Chunk size for multipart uploads.

Files are uploaded to the storage in parts of this size. Each part is
buffered in memory while it is uploaded so it can be retried.

The chunk size is increased automatically if needed to keep the number
of parts below 10,000.

Properties:

- Config:      chunk_size
- Env Var:     RCLONE_GUANGYADRIVE_CHUNK_SIZE
- Type:        SizeSuffix
- Default:     8Mi

#### --guangyadrive-encoding

Path encoding for GuangYaPan.

Properties:

- Config:      encoding
- Env Var:     RCLONE_GUANGYADRIVE_ENCODING
- Type:        Encoding
- Default:     Slash,InvalidUtf8,Dot

#### --guangyadrive-description

Description of the remote.

Properties:

- Config:      description
- Env Var:     RCLONE_GUANGYADRIVE_DESCRIPTION
- Type:        string
- Required:    false

## Backend commands

Here are the commands specific to the guangyadrive backend.

Run them with:

```console
rclone backend COMMAND remote:
```

The help below will explain what arguments each command takes.

See the [backend](/commands/rclone_backend/) command for more
info on how to pass options and arguments.

These can be run on a running backend using the rc command
[backend/command](/rc/#backend-command).

### addurl

Add offline download task for url.

```console
rclone backend addurl remote: [options] [<arguments>+]
```

This command adds an offline (cloud-side) download task for a url
(http, magnet or ed2k). For a torrent all of its files are downloaded.
It is also available as "offline".

Usage examples:

```console
rclone backend addurl guangyadrive:dirpath url
rclone backend addurl guangyadrive:dirpath url -o name=custom_name
```

Downloads will be stored in 'dirpath', which must exist.

The result is the new task as JSON with the fields "id", "name",
"url", "size", "status" ("init") and "created_at".

Options:

- "name": Custom name for the downloaded file or directory.

### tasks

List offline download tasks.

```console
rclone backend tasks remote: [options] [<arguments>+]
```

This command lists the offline download tasks. It is also
available as "listoffline".

Usage example:

```console
rclone backend tasks guangyadrive:
```

The result is a JSON list of tasks with the fields "id", "name",
"url", "size", "status" ("init", "running", "complete" or "error"),
"progress" (percentage), "error_msg" and "created_at".

### deltask

Delete an offline download task.

```console
rclone backend deltask remote: [options] [<arguments>+]
```

This command deletes the offline download task with the given ID.
It is also available as "deleteoffline".

Usage example:

```console
rclone backend deltask guangyadrive: task_id
```

## Limitations

- No hashes, so `rclone check` compares sizes only.
- Modification times can't be set.
