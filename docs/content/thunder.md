# Xunlei Drive

The `thunder` backend accesses [Xunlei Drive](https://pan.xunlei.com/)
(Thunder). It can also be selected with the type names `xunlei` and
`thunderdrive`.

Paths are specified as `remote:path`, and may be as deep as required, e.g.
`remote:directory/subdirectory`.

## Configuration

Run `rclone config` and choose `thunder`. Enter your username and password, or
a refresh token. The backend identifies itself as an Android client;
`device_id` is generated if left empty. Refresh tokens are rotated and saved
automatically.

```ini
[mythunder]
type = thunder
username = 13800138000
password = *** ENCRYPTED ***
```

### Hashes

Xunlei identifies content by GCID, which rclone registers as the hash type
`gcid`. `rclone check`, `--checksum` and `rclone hashsum gcid` work against
local files.

### Uploads and rapid upload

The GCID is needed before an upload starts. When the source provides it (a
local file computes it by reading the file) the data is streamed to S3: a single
PUT below `upload_cutoff`, otherwise a multipart upload using `chunk_size` ×
`upload_concurrency` of memory. Only when the GCID can't be obtained, or the
size is unknown, is the input copied to a temporary file while hashing. If
Xunlei already has the content the file is created without transferring data.

### Offline downloads

`rclone backend addurl remote:dir URL`, `tasks` and `deltask` manage offline
download tasks; the rc offers `operations/addurl`, `operations/listoffline`
and `operations/deleteoffline`. Deleting a task keeps the downloaded files.

### Modification times

Modification times are not supported.

### Advanced options

Here are the Advanced options specific to thunder (Xunlei Drive).

#### --thunder-device-id

32-character hexadecimal device ID (generated automatically if blank)

Properties:

- Config:      device_id
- Env Var:     RCLONE_THUNDER_DEVICE_ID
- Type:        string
- Required:    false

#### --thunder-root-folder-id

Root folder ID.

Leave blank normally to use the root of the drive.

Properties:

- Config:      root_folder_id
- Env Var:     RCLONE_THUNDER_ROOT_FOLDER_ID
- Type:        string
- Required:    false

#### --thunder-upload-cutoff

Cutoff for switching to chunked upload.

Any files larger than this will be uploaded in chunks of chunk_size.
The minimum is 0 and the maximum is 5 GiB.

Properties:

- Config:      upload_cutoff
- Env Var:     RCLONE_THUNDER_UPLOAD_CUTOFF
- Type:        SizeSuffix
- Default:     200Mi

#### --thunder-chunk-size

Chunk size for multipart uploads.

Note that this is stored in memory and there may be up to
"--transfers" * "--thunder-upload-concurrency" chunks stored at once
in memory.

Rclone will automatically increase the chunk size when uploading a
large file of known size to stay below the 10,000 chunks limit.

Properties:

- Config:      chunk_size
- Env Var:     RCLONE_THUNDER_CHUNK_SIZE
- Type:        SizeSuffix
- Default:     5Mi

#### --thunder-upload-concurrency

Concurrency for multipart uploads.

This is the number of chunks of the same file that are uploaded
concurrently for multipart uploads.

Properties:

- Config:      upload_concurrency
- Env Var:     RCLONE_THUNDER_UPLOAD_CONCURRENCY
- Type:        int
- Default:     4

#### --thunder-encoding

The encoding for the backend.

See the [encoding section in the overview](/overview/#encoding) for more info.

Properties:

- Config:      encoding
- Env Var:     RCLONE_THUNDER_ENCODING
- Type:        Encoding
- Default:     Slash,LtGt,DoubleQuote,Colon,Question,Asterisk,Pipe,BackSlash,Ctl,LeftSpace,RightSpace,RightPeriod,InvalidUtf8,Dot

#### --thunder-description

Description of the remote.

Properties:

- Config:      description
- Env Var:     RCLONE_THUNDER_DESCRIPTION
- Type:        string
- Required:    false

## Backend commands

Here are the commands specific to the thunder backend.

Run them with:

```console
rclone backend COMMAND remote:
```

The help below will explain what arguments each command takes.

See the [backend](/commands/rclone_backend/) command for more
info on how to pass options and arguments.

These can be run on a running backend using the rc command
[backend/command](/rc/#backend-command).

### addurl

Add offline download task for url.

```console
rclone backend addurl remote: [options] [<arguments>+]
```

This command adds an offline (cloud-side) download task for a url
(http, magnet or ed2k). It is also available as "offline".

Usage examples:

```console
rclone backend addurl thunder:dirpath url
rclone backend addurl thunder:dirpath url -o name=custom_filename.zip
```

Downloads will be stored in 'dirpath', which must exist.

The result is the new task as JSON with the fields "id", "name",
"url", "size", "status" ("init"), "progress" and "created_at".

Options:

- "name": Custom filename for the downloaded file.

### tasks

List offline download tasks.

```console
rclone backend tasks remote: [options] [<arguments>+]
```

This command lists the offline download tasks. It is also
available as "listoffline".

Usage example:

```console
rclone backend tasks thunder:
```

The result is a JSON list of tasks with the fields "id", "name",
"size", "status" ("running", "complete" or "error"), "progress"
(percentage), "error_msg" and "created_at".

### deltask

Delete an offline download task.

```console
rclone backend deltask remote: [options] [<arguments>+]
```

This command deletes the offline download task with the given ID.
Files already downloaded are kept. It is also available as
"deleteoffline".

Usage example:

```console
rclone backend deltask thunder: task_id
```

## Limitations

- Deleted files go to the trash.
